## Part A: screen changes ([decision](../decisions/2026-11-17-screens-and-name.md))

- **Saving:** savings-goal categories get their own "Saving" section on Spending, after spending. Home's spent-vs-budget bar counts spending only; add a one-line "Saved this month: $X of $Y". How the app tells a saving category from a spending one is your call (for example the group name, or a setting Antonio flips per group); explain it in the report.
- **Spending:** over-budget and in-progress categories stay visible; categories on track or not started fold under one row ("12 on track", tap to open).
- **Bills:** a "Not a bill" button on each bill, saved in the app's own storage like "Fine"; a way to undo it (for example a "Hidden" list at the bottom of Bills).
- **Version check:** add `getServerVersion` to [../specs/actual-access.md](../specs/actual-access.md) (reason: warn when Actual and the app differ) and show a banner on every screen if the server's version isn't the `@actual-app/api` version.

## Part B: the install and the updater ([decision](../decisions/2026-11-17-deploys.md))

Write these in `deploy/` and test everything you can on the NUC (without Docker, with stand-ins, or in a throwaway folder). Target: the OptiPlex (Debian 12, Docker with the compose plugin, Actual published on host port 5006, Caddy reaching apps through `host.docker.internal:<port>`).

**Bootstrap** (`deploy/bootstrap.sh`, small enough to paste): Antonio pastes it on the OptiPlex and runs it with `sudo`. It:
1. creates a read-only SSH deploy key for this repo (root-owned, `/opt/finance/deploy-key`), prints the public key, and waits while he adds it on GitHub (Settings → Deploy keys, read access only)
2. clones the repo's `deploy` branch to `/opt/finance/src` (root-owned) and runs `deploy/install.sh` from it

**Install** (`deploy/install.sh`, run as root, safe to run again):
- **User and folders:** system user `finance` (no login, no shell, no sudo, not in `docker`); `/opt/finance/` owned by root; `data/` owned by `finance`; `secrets/finance.env` mode 600, readable only by the app's user.
- **Secrets:** asks at hidden prompts for the Actual server password and a new app password (twice), and at a normal prompt for the budget's Sync ID (Actual → Settings → Advanced). The Actual password is stored as typed (the app needs it to log in); the app password only as a hash (use the app's own hashing, for example by running the built image once). No encryption password ([decision](../decisions/2026-11-17-encryption-off.md)). Nothing is echoed, logged or written anywhere else.
- **Compose** (root-owned `/opt/finance/compose.yml`, copied at install; the updater never changes it):
  - the app runs as the `finance` user, read-only, `cap_drop: ALL`, `no-new-privileges`, only `data/` writable, the secrets file mounted read-only, `TZ=America/New_York`
  - **no way out:** the app is only on an `internal` network, with no route to the internet
  - a small forwarder with a fixed, root-owned config (a pinned stock image) is the only bridge: it lets the app reach Actual (host port 5006) and lets Caddy reach the app. Its published port binds to the Docker bridge's gateway address, not to the home network, so only containers on the OptiPlex (Caddy) reach it. Choose the forwarder and the exact wiring from the official docs and explain them in the report.
  - Actual's own compose file stays untouched.
- **Updater:** a root systemd timer every 5 minutes: fetch the `deploy` branch with the deploy key; if it moved, build the image, start it, and if `/healthz` isn't `ok` within a few minutes, go back to the previous image. Keep the previous image for rollback. It never changes the compose file, the networks, the folders or the secrets.
- **Logs:** the updater's log has commits, steps and up/down only.
- Print at the end: what was installed, and the next steps for Antonio (log in on his phone, switch off the accounts that aren't his).

**`/healthz`:** answers `ok` or `error` and the running commit, nothing else (update the test).

**Uninstall** (`deploy/uninstall.sh`): stops and removes the app, the forwarder, the timer and the user; asks before deleting `/opt/finance`.

**Paste-ready:** in the report, the exact bootstrap command for Antonio, short enough to paste into a terminal over SSH (a pasted script once got cut off at ~20,000 characters; a checksummed base64 block avoids that).
