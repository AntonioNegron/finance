## Part B: the fake Actual server

- Run an Actual server on the NUC, listening on localhost only, with Docker if the NUC has it, otherwise the way Actual's docs describe without Docker. Pin the version (the newest stable for now; Phase 1 matches it to Antonio's server).
- Its throwaway password lives in a git-ignored `dev/.env`.
- `dev/seed.ts`: builds the budget in [../specs/fake-budget.md](../specs/fake-budget.md) with the API's import functions (per the docs), the same every run. The seed script may use write functions; the app may not.
- One command starts the fake server and seeds it: `npm run dev:fake`. Fill in the spec with what you built.

## Part C: the app

Node.js + TypeScript, the official `@actual-app/api` package (pinned), served by a small web server; the page itself is phone-first.

**Reading Actual:**
- Only the functions you list in [../specs/actual-access.md](../specs/actual-access.md), each with the reason. No write, import or bank-sync functions.
- Download the budget into the app's own data folder and sync it on a timer and when Antonio pulls to refresh. Show "last synced" on every screen.
- Settings for the connection come from environment variables (server URL, budget sync ID, data folder) and a secrets file path (server password, encryption password if any, the app's login hash). Names go in `.env.example`; values never in the repo.

**Screens** (a phone 390 px wide first; big tap targets; stacked lists, never wide tables; light and dark):
1. **Home:** total balance of the counted accounts, this month's spending vs. budget as one bar, money left to spend, the next three bills.
2. **Categories:** spent vs. budgeted this month per category, over-budget first; tap a category for its transactions this month. A month switcher.
3. **Bills & subscriptions:** recurring charges found from the history (and Actual schedules if any): next date, amount, total per month; flag price increases.
4. **Unusual:** duplicates, charges much larger than usual for that payee, new payees above a threshold. Antonio can mark one "fine"; that's saved in the app's own storage, never in Actual.
5. **Accounts & settings:** balances per account; a switch per account for "count in totals" (saved in the app's own storage).

No budget builder yet (Phase 2).

**Login:** its own password on every route except `/healthz` (which answers only `ok` or `error`). Store only a hash (a slow, standard password hash). Session cookie: secure, http-only, same-site strict, 30 days. In dev, a dev password from `dev/.env`. Lock out for a while after repeated wrong passwords.

**Logging:** events and counts only (for example "synced, 42 new transactions"), never amounts, payees, account or category names, notes or dates. Errors in logs carry an error code and the function name, not the data.

## Part D: guardrail tests

`npm test` runs all of these and fails on any problem:
- **Allowed functions:** scan `app/` and fail if it uses any Actual API function not in [../specs/actual-access.md](../specs/actual-access.md). (`dev/` is exempt.)
- **No data in logs:** start the app against the fake budget, open every screen and action, capture all logs, and fail if any fake amount, payee, account name, category name or note shows up.
- **Login everywhere:** every route but `/healthz` refuses without a session; `/healthz` returns nothing but `ok` or `error`.
- **No way out:** the built page loads nothing from outside (no outside URLs in the built files, a strict Content Security Policy).
- **Secret scan** of the repo.

## Part E: container

- `deploy/Dockerfile`: pinned base image, runs as a non-root user, read-only filesystem except its data folder, health check on `/healthz`.
- `deploy/docker-compose.example.yml`: the app with no published port, a comment marking where Phase 1 adds the private network to Actual and the route from Caddy. No secrets.
- Build the image on the NUC to prove it builds, and run it against the fake server once.
