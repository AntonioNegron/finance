## How saving categories are told apart

- **By category group.** A group counts as saving if its name contains "sav", "goal" or "invest" (case doesn't matter). The fake "Savings Goals" matches this way.
- **Antonio can switch any group** on Spending → "Which groups are saving?". Each group shows "guessed from the name" or "your choice". His choice wins over the guess, and is saved in the app's own storage (`app-state.json`), never in Actual.
- **"Saved this month"** is the money that left his accounts under saving categories (for example a transfer to an investment account categorized "Investing"). It is shown against the amount budgeted to saving categories.
  - Not counted: money budgeted to a goal that stays in checking, and transfers between two on-budget accounts (Actual gives those no category).
  - On the fake budget: $100.00 of $450.00.
  - If he'd rather see something else here, it's a small change.

## The network and the forwarder

```
phone ─▶ Caddy ─▶ 172.17.0.1:8015 ─▶ forwarder:8080 ─▶ app:8080
app ─▶ forwarder:5006 ─▶ host.docker.internal:5006 (Actual)
```

- **The app** is only on `inside`, a Docker network with `internal: true`. Docker gives it no gateway, so the app has no route to the internet, the home network or even the OptiPlex itself. It publishes no port.
- **The forwarder** (HAProxy, a pinned stock image) is on `inside` and on `outside`, a normal network of its own. Its config is root-owned and fixed: two plain TCP forwards and nothing else.
  - `:8080` → the app
  - `:5006` → Actual on the OptiPlex's port 5006
  - With no `log` line, it logs nothing. It runs read-only, with no capabilities.
- **Caddy's way in:** the forwarder's port 8080 is published as `172.17.0.1:8015`, the Docker bridge's own address. Caddy reaches it as `host.docker.internal:8015`, the same way it reaches Authelia on 9091. The home network can't reach the forwarder: it isn't published on the OptiPlex's LAN address.
- **Why the app stays off the internet:** anything the app sends that isn't to the forwarder's two ports goes nowhere. The forwarder only accepts connections and passes them to two fixed places, so it can't be told to go anywhere else.
- **Why HAProxy:** it is a stock, widely used TCP forwarder whose whole behavior lives in one config file; the official image runs as a non-root user; and the 3.2 branch has long-term support. Docker's internal DNS (`127.0.0.11`) lets it find the app again after the updater recreates it.
- **Logs:** both containers log through the syslog driver to the OptiPlex's journal (`journalctl -t finance-app`), with Docker's dual-logging cache turned off. With that cache off, `docker logs` can't read them, and so neither can Dozzle or anything else that reads Docker's logs.

## Dozzle and Actual's logs (Antonio decides)

- **Finance containers: done** without touching Dozzle. Their logs go to the journal only, so Dozzle can't read them. They still appear in Dozzle's container list (name, state, memory), but with no logs.
- **Actual: not done.** Dozzle's only control is `DOZZLE_FILTER`. Its docs describe it as a positive Docker filter: it chooses which containers to show, with no way to exclude one. There is no hide label. So Actual can't be hidden without touching Actual's compose file, which this task rules out.

The options:
1. **(Suggested) In manual step 2, while Antonio edits Actual's compose file anyway** to pin 26.11.0, he also adds the same logging block the finance app uses, under Actual's service:
   ```
       logging:
         driver: syslog
         options:
           syslog-address: unixgram:///dev/log
           tag: "{{.Name}}"
           cache-disabled: "true"
   ```
   Actual's logs then live only in the OptiPlex's journal (`sudo journalctl -t <actual's container name>`). Dozzle, `docker logs` and `optiplex logs` can no longer read them.
2. **Turn Dozzle into an allow-list:** set `DOZZLE_FILTER=label=dozzle.show=true` on Dozzle and add that label to every other container. Most of them are standalone containers or compose apps Claude Code doesn't manage, so each would need recreating. That's a lot of change.
3. **Leave it.** The app doesn't rely on Dozzle. Its own logs carry no data either way. But I can't say what Actual's logs contain, because I haven't read them and won't.

- **"On track" vs. "in progress":**

  - Saved by bill key in `app-state.json`: the payee for bills found from history, the schedule id for Actual schedules.
  - A hidden bill leaves the monthly total and Home's next bills, and moves to "Hidden (not bills)" with Undo.
  - Each bill's amount now sits under its name, so the button fits on a phone.
- **Version banner:**
  - `getServerVersion` runs on each sync; the app's version comes from the installed `@actual-app/api` package.
  - Not shown on the login page, so the version isn't shown to anyone before login.
  - Not shown if the server doesn't report a version.
  - The sync log line gains `server_version_match=1|0`.
- **`/healthz`:** `ok <commit>` or `error <commit>`. The commit comes from `FINANCE_COMMIT`, set at image build (`--build-arg`), and is `unknown` otherwise.
- **The Sync ID lives in the secrets file:** the install keeps everything Antonio types in one root-and-finance-only file. The app reads it from there when it isn't in the environment (dev still uses the environment).
- **The updater runs a root-owned copy** (`/opt/finance/bin/finance-update`), never the script in the cloned repo. Moving `deploy` can change the app image, but not what root runs, the compose file, the networks or the secrets. The build itself runs in Docker's build sandbox, with the repo as its only input.
- **The updater's rules:**
  - It checks every 5 minutes, and 1 minute after the install.
  - It waits up to 3 minutes for `ok <new commit>`.
  - It keeps two images: `current` and `previous`.
  - A failed commit is remembered and not retried; ship a new commit instead.
  - The build output goes to `state/last-build.log` (root only), not to the journal, so the log stays commits, steps and up/down.
- **Health depends on Actual:** `/healthz` is `ok` only after a successful sync, so an update made while Actual is down rolls back. That's the safe side; the next commit tries again.
- **Port 8015:** the next free one after the guest page (8014) in the homelab inventory. The install stops if something else holds it.
- **GitHub host key pinned:** GitHub's Ed25519 host key is pinned in `/opt/finance/known_hosts` with `StrictHostKeyChecking=yes`, so a fake GitHub is refused.
- **Install prompts:** they read from the terminal through one opened file, so a test can feed answers. `FINANCE_BASE`, `FINANCE_SYSTEMD_DIR`, `FINANCE_TTY` and `FINANCE_REPO` exist only for the dry-run test. `sudo` resets the environment, so they can't be set by accident on the OptiPlex.
