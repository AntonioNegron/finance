## How to run it

On the NUC, in `~/workspace/finance`:

```
npm install
```
- installs the pinned packages
- turns on the secret-scan hook for commits

```
npm run dev:fake
```
- starts a fresh fake Actual server on `127.0.0.1:5007` and seeds the fake budget
- leave it running; Ctrl-C stops it

In a second terminal:

```
npm run dev:app
```
- the app on `http://127.0.0.1:5180`
- the password is `DEV_APP_PASSWORD` in `dev/.env`

```
npm test
```
- runs the typecheck, every guardrail test and the secret scan
- needs the fake server running

```
npm run screens
```
- retakes the screenshots into `docs/screens/`

Other clones get the commit hook from `npm install`: its `prepare` script runs `git config core.hooksPath .githooks`. The hook downloads gitleaks into `.tools/` on first use.

## Implementation calls the task didn't spell out

- **Fake server without Docker:** the official `@actual-app/sync-server` npm package, pinned, as a dev dependency. Its data is wiped on every `npm run dev:fake`, so each run is fresh.
- **Throwaway passwords:** `dev/.env` is created with random values on first run (git-ignored).
- **Fake budget dates:** 12 months ending on the real "today" (or `FAKE_TODAY`), so the screens always show a current month. The same day always gives the same budget.
- **Web server:** plain `node:http`, no framework. Pages are rendered on the server, plus one small script for pull-to-refresh. There is no front-end build, so nothing gets bundled from outside.
- **Password hash:** scrypt (N=2^15, r=8, p=1), built into Node. No extra package.
- **Making the login hash:** `npm run hash-password` asks at a hidden prompt and prints the hash for `FINANCE_LOGIN_HASH`.
- **Lockout:** 5 wrong passwords in a row lock all logins for 15 minutes. It's global, not per address, because behind Caddy every request comes from Caddy. Downside: someone guessing could keep Antonio locked out; Phase 1's Authelia in front makes that unlikely.
- **Sessions:** random tokens; only their SHA-256 is stored, in the app's own file. Cookie `fin_session`, HttpOnly, SameSite=Strict, 30 days, and Secure unless `FINANCE_SECURE_COOKIE=false` (dev only, plain http). Form posts from another site are also refused by an Origin check.
- **Logs:** a fixed list of event names and numbers only; nothing else can be written. All other console output is silenced, because `@actual-app/api` prints its own messages, including budget file paths. Errors log only the function name and Actual's error code.
- **Not used:** `aqlQuery`/`runQuery`, though they are read-only. A general query could read anything, and the named functions are enough. Listed in the spec as "not used".
- **Data kept:** 13 months of transactions are read on each sync; the month switcher goes back that far.
- **Counted accounts:**
  - Every open account counts by default, off-budget ones included, so the total is net worth.
  - "This month's spending" counts only on-budget accounts that are switched on.
  - Leaving an account out removes it from every total, spending included.
- **Bills:** a payee is a bill if it charged in at least 3 of the last 6 months, about once a month, within 4 days of the same day of the month, and within 30% of its typical amount. Bills whose amount changes show "varies" and a typical amount.
  - A price increase is a step up between two runs of steady charges.
  - Actual schedules are merged in, and their next date is used.
  - Side effect: a regular monthly outing (the fake "Cinema 8") also counts as a bill.
- **Unusual (last 45 days):**
  - Duplicates: same account, payee and amount within a day.
  - "Larger than usual": more than 3× the payee's typical charge and over $50 more, after at least 4 earlier charges.
  - New payees: a first charge of $100 or more.
  These thresholds are guesses to tune once Antonio sees them on his own data.
- **"Fine" marks and account switches:** saved in `app-state.json` in the app's data folder, never in Actual.
- **Sync:** every 15 minutes (`FINANCE_SYNC_MINUTES`), on pull-to-refresh, and on the ↻ button. If a sync fails, the screens say "last sync failed" and keep the last data; `/healthz` says `error`.
- **`/healthz`:** `ok` only after a successful sync, so the container health check also shows whether Actual is reachable.
- **Strict CSP:** `default-src 'none'`, self only, with no inline scripts or styles. The spending bars use width classes in 5% steps instead of inline widths.
- **Install scripts:** npm 11 asked about install scripts for `better-sqlite3`, `argon2`, `bcrypt` and `esbuild`. All four are denied in `package.json` (`allowScripts`), because they ship prebuilt binaries that load fine. The Dockerfile uses `--ignore-scripts` too.
- **Screenshots without sudo:** the NUC lacks the system libraries headless Chromium needs. `scripts/pw-libs.sh` downloads those Debian packages with `apt-get download` (no root) and unpacks them into `~/.local/share/finance-pw-libs`; only `npm run screens` uses that folder. To undo: `rm -rf ~/.local/share/finance-pw-libs`. Playwright's browser is in `~/.cache/ms-playwright`.
- **Compose example:** `TZ` and `ACTUAL_SYNC_ID` are placeholders for Phase 1, because I don't know Antonio's time zone.
- **Workspace:** added `finance/` to `~/workspace/CLAUDE.md` (that file is outside any repo, so it isn't committed).
